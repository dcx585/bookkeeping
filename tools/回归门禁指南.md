# 回归门禁落地指南（本项目专用）

> 目标：每次改动后自动发现「改 A 破坏 B」。
> 全部工具已提交到 `tools/`，本地与 CI 共用同一份，`sh tools/check.sh` 一条命令。

## 0. 先看已修掉的真 bug

`build-apk.yml:733` 原来是顶格写的：

```
              }
private static void queueAppend(File dir, String entry) {   ← 缩进 0
                  synchronized (LOCK) {
```

heredoc 内容行顶格 → 该行在 YAML 里跳出 `run: |` 块 → **整个 workflow 变成非法 YAML**
→ GitHub 直接拒绝加载 → push 后不构建、**也不发失败通知**。
症状是「APK 一直是旧版本，但 CI 页面看着没问题」，排查成本极高。
`python3 -c 'import yaml'` 一下就能抓到。现已修为 14 空格缩进。

## 1. 一条命令

```sh
sh tools/check.sh          # 本地
```

CI（`.github/workflows/gate.yml`）跑的就是这一行 —— **不搞两套标准**。

## 2. 七层门禁各防什么

| # | 检查 | 防住 | 防不住 |
|---|---|---|---|
| 1 | `wfcheck.sh` YAML 可解析 + heredoc 缩进 | workflow 静默失效 | 逻辑错误 |
| 2 | `node --check` 内联 JS | 白屏页面 | 运行期错误 |
| 3 | `selftest.js`（逻辑/回归/金标准） | 行为变化 | 没测到的路径 |
| 4 | `heredoc_check.js` + `JOTest` | Java 花括号断裂 | Android API 误用 |
| 5 | `contract_check.js` | Java 改名→网页静默失效 | 返回格式变化 |
| 6 | `menu_snapshot.sh` 按钮指纹 | 按钮 onclick 被改/删 | 按钮内部逻辑 |
| 7 | `jbcheck.sh --self` | 数据写入残缺 JSON | 语义错误 |

## 3. 金标准快照（零依赖）

```sh
cd tools/selftest
UPDATE_GOLDEN=1 node golden_test.js   # 行为确实该更新时：重录
node golden_test.js                   # 平时/CI：不一致就 exit 1
```

金标准存 `golden.json`，人类可读，`git diff` 就是 code review 材料。

关键点：**冻住 `Date.now()`**。快照最怕时间戳/随机数/顺序漂移，
`golden_test.js` 里用 `Date.now = () => T` 固定时钟，否则每次跑都红。

## 4. Git hooks（不用 husky）

```sh
sh tools/install_hooks.sh      # 设置 core.hooksPath = tools/hooks
```

- `pre-commit`：快。只查语法 + 结构 + 数据文件；改了 `app.html`/`tools/` 才跑全套。
- `pre-push`：慢。推之前跑全套（此时拦下来收益最大）。
- **不适用 husky**：本项目没有 `node_modules`、没有 `package.json`。
  husky 需要 `npm install` 写 `.git/hooks`，对一个单文件 HTML 项目是纯负担。
  `core.hooksPath` 是 git 原生能力，hook 脚本进版本库，换机器自动生效。

### 绕过与反绕过（重要）

| 绕过方式 | 是否可行 | 反制 |
|---|---|---|
| `git commit --no-verify` | ✅ 可行（已验证） | CI 兜底：`gate.yml` 与 branch protection |
| `git push --no-verify` | ✅ 可行 | 同上；推送后 CI 仍会红 |
| `FORCE=1 git commit` | ✅ 可行（打印失败项但不拦） | 留痕，应急用 |
| 改 `tools/check.sh` 让它永远 exit 0 | ✅ 可行 | `selftest.js` 元检查 + CI 里 grep `exit $FAIL` |

**结论：本地 hook 只是「早发现」，唯一真正的闸门是 CI + branch protection。**

## 5. CI 门禁（真正挡住的那一步）

`.github/workflows/gate.yml` 的 job 名是 `Gate`。然后必须手动做一次：

> GitHub → 仓库 Settings → Branches → Add branch protection rule
> → Branch name pattern: `master`
> → ✅ Require status checks to pass before merging
> → 勾选 **Gate**（必须先在 Actions 里成功跑过一次，否则列表里搜不到）
> → ✅ Require branches to be up to date before merging

没做这一步，`gate.yml` 只是「发通知」——**红色叉号不影响任何操作**，
坏代码照样能合进 master。这是 90% 的个人项目门禁失败的真正原因。

注意 `build-apk.yml` 的 `paths:` 是白名单，`tools/**` 已加入，
否则「偷偷放宽门禁」的那次提交不会触发构建。

## 6. 数据安全网

见 `tools/datasafety.js.txt`（把内容贴进 `app.html` 的 `<script>` 末尾）：

- `SCHEMA_VERSION` + `migrateTx(arr, fromV)` 纯函数迁移（可单测）
- `snapshotBeforeWrite()` 每次用户操作前拍快照，留最近 7 份
- `loadWithMigration()` 解析失败**不清空**，改为隔离 + 提示恢复
- 导出备份带 `schemaVersion`，导入前先拍快照

## 7. 覆盖率为什么不是答案

本项目 **0% 覆盖率**（没有 instrumentation），但门禁有效；
反过来，即使 100% 行覆盖，下面这条也抓不到：

```js
// 100% 覆盖，但测试只喂了 10 分钟内的样本
if (Math.abs(ot - t) > WINDOW) continue;
const WINDOW = 10 * 60 * 1000;   // 有人改成 20*60*1000 → 覆盖率不变，行为已变
```

覆盖率测的是「**代码语句被执行过没有**」，不是「**断言检查了没有**」。
没断言的执行只算「跑过」，不算「验过」。
所以金标准快照（第 3 层）比覆盖率有用得多。

## 8. 优先级（业余开发者，3 件事）

1. **修那行顶格 + 让 `gate.yml` 成为 required check**（半天，收益最大）
   现在你的 CI 是**静默失效**的，等于没有。
2. **金标准快照 `golden_test.js`**（1–2 小时，之后改代码心里有底）
   这是抓「改 A 弄坏 B」的主力，零依赖、可读、git 能 diff。
3. **`core.hooksPath` + `check.sh`**（1 小时，省掉往返等 CI 的时间）
   注意它是「早发现」不是「闸门」。
